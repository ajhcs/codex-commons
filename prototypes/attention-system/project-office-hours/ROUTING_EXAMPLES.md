# Routing examples

These examples exercise every destination without turning Office Hours into a general inbox.

| # | Situation | Route | Why |
| --- | --- | --- | --- |
| 1 | Real dogfood use shows that the Product model Wiki prevented a repeated architecture investigation. | Post finding | The result is reusable, evidence-backed, and may change how other tasks orient. |
| 2 | The blocked bridge task now has a verifiable dependency exit condition. | Task update | This changes executable acceptance and blocked state, not communal discussion. |
| 3 | Fail-open behavior for an unavailable Commons service becomes settled guidance. | Wiki revision | Fresh Codex tasks need one current source of truth. |
| 4 | A failing migration blocks the command the human is actively waiting on. | Active Codex chat | The human decision is immediate and tied to controlled live work; batching would be harmful. |
| 5 | A verified live reviewer is already checking the same patch and needs one file reference. | Direct A2A | The audience is one known reachable session and the handoff is narrow. |
| 6 | A contributor session appears only in last week's historical provenance. | Stay silent | Provenance is not current presence, reachability, or permission to contact that session. |
| 7 | Tests pass exactly as the task acceptance requires and the task event already records it. | Stay silent | The canonical task already carries the result; another Post would add noise. |
| 8 | A milestone review exposes two plausible bridge boundaries with current evidence on both sides. | Office Hours → decision Post | The question can wait for deep review; only the settled decision becomes durable. |
| 9 | A README typo is fixed within the current Codex task. | Stay silent | The correction needs no separate coordination record. |
| 10 | An ambiguous provider response requires an operator choice before active work can continue. | Active Codex chat, then decision Post | Ask immediately because work is blocked; record the consequential settled choice afterward. |

## Examples rejected from Office Hours

- “Five tests passed” with no changed action.
- “Agent X is online” inferred from an old session ID.
- A general request to assign work to an agent.
- A question already open in a canonical Post.
- A background summary generated only because an interval elapsed.
- A low-confidence idea without evidence or a defined audience.
