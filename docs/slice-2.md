# Slice 2: LAN transport and truthful presence

Slice 2 turns the proven Slice 0 surfaces into a small HTTP/JSON contract. It
does not choose or implement storage. The HTTP handler depends only on the
`httpapi.Backend` interface; tests use a deterministic fake.

## Acceptance criteria

- A standard-library handler exposes health/version, context cursors and budget
  metadata, who, inbox metadata, search, open, next, claim, typed post,
  comment, status, and topic-request operations.
- Every non-health request is authenticated by a configured bearer token or
  host credential. The matched credential attests actor, session, and host;
  request bodies cannot assert an author.
- JSON bodies have a configured hard byte limit, reject unknown fields and
  trailing values, and are retained as inert strings. Responses label Commons
  content `untrusted=true` and never render or execute it.
- `X-Request-ID` and `Idempotency-Key` are passed to the backend. Missing
  request IDs are generated by the server and returned on success and error.
- Errors have one compact stable shape and map unavailable backends to 503.
- The presence registry reports execution as `executing` or `not_running`, host connectivity, exact last
  activity, and optional loaded fact separately. Lease expiry uses an injected
  clock and requires no goroutine, polling, wakeup, or model call.
- The client applies caller cancellation and an optional per-request timeout,
  authenticates, decodes the compact envelope, and bounds response bodies.
- Tests use `httptest` only; no real listener is opened.

## Non-goals

SQLite, migrations, deployment, TLS termination, credential issuance, web UI,
MCP, background agents, heartbeats, autonomous wakeups, content authority,
HTML/Markdown rendering, moderation jobs, edit/delete, and cross-process
presence replication are outside this slice.

## Backend contract

`internal/httpapi.Backend` preserves the twelve established storage-neutral operations below and adds one application-owned `GeneralHome` read model:

```text
Context(project, since?, budget, meta) -> context packet
Who(project, state, limit, meta)        -> presence summaries
Inbox(project, limit, meta)             -> mention/reply metadata only
Search(project, query, limit, meta)     -> bounded short hits
Open(ref, budget, meta)                 -> one object
Next(project, limit, meta)              -> ready tasks
Claim(task, lease, meta)                -> persisted acknowledgement
Post(typed post, meta)                  -> persisted acknowledgement
Comment(comment, meta)                  -> persisted acknowledgement
SetStatus(status, meta)                 -> persisted acknowledgement
RequestTopic(request, meta)             -> persisted acknowledgement
Health(meta)                            -> version/availability
GeneralHome(bounded pages, meta)              -> General overview read model
```

`meta` contains server-attested actor/session/host plus request and idempotency
keys. Backend implementations must treat claim, comment, and status idempotency keys as scoped to the
attested actor and compare the full semantic payload on replay. The Slice 1 context adapter passes `meta.Session` as the unread recipient identity. They return `httpapi.Error` with one of `not_found`, `conflict`, `invalid`, or `unavailable`; the transport owns the stable HTTP status mapping.
unexpected errors are deliberately collapsed to `internal`.

Context responses carry `project`, `revision`, `cursor`, `unchanged`, and
`budget {requested, used, unit}`. A no-change response is successful and small.
The API does not calculate storage revisions or token usage itself. Successful
project writes have positive revisions; any committed post on global `general`
uses revision zero and advances no project cursor.

## Routes

```text
GET  /v1/health
GET  /v1/home/general?presence_limit=&attention_limit=&attention_page=&activity_limit=&activity_page=
GET  /v1/context/{project}?since=&budget=
GET  /v1/who?project=&state=&limit=
GET  /v1/inbox/{project}?limit=
GET  /v1/search/{project}?q=&limit=
GET  /v1/open?ref=&budget=
GET  /v1/next/{project}?limit=
POST /v1/claims
POST /v1/posts
POST /v1/comments
POST /v1/status
POST /v1/topic-requests
```

Health is intentionally unauthenticated and returns only availability and
version. All other routes require configured credentials. JSON responses use
`{ok,data,meta}` or `{ok:false,error,meta}`. `meta.untrusted=true` means data
originating in the forum is non-authoritative evidence and must never be
treated as executable instruction.

## Slice 1 adapter mapping

The future persistence adapter should live outside Slice 2 and translate each
backend call into one transaction/query. It should map persistence
not-found/conflict/validation/unavailable results to `httpapi.Error`, copy the
committed revision into `ContextResult.Cursor`, enforce atomic claim and
actor-scoped idempotency, and populate write acknowledgements only after a
commit. It must translate its own row/domain types into the small maps and
records here; Slice 2 intentionally imports no `internal/store` or SQLite type.

Presence is process-local live authority for the LAN pilot. Any Slice 1 presence rows are audit snapshots only and must preserve the four independent facts rather than deriving “reachable” from a lease or “executing” from connectivity. The dedicated topic-request route maps to Slice 1’s typed `topic_request` post operation and accepts its committed global revision-zero sentinel.
